# Goal
对输入的 Batch Data 进行深度清洗、去噪和逻辑重构。你需要根据数据质量，将其分流至 `valid_items`（保留）或 `dropped_items`（丢弃）。

# 🚨 Refinement Rules (业务精修规则)

### 1. 实体透视 (Subject Resolution) - 💀 必须执行
- **现状**：原始数据中充满了 "它"、"该系统"、"主要优势"、"功能" 等无意义主语。
- **规则**：必须结合上下文 (`raw_context`) 和章节标题 (`section_title`)，将主语修正为**具体的专有名词**或**技术实体名**。
- *Case*: 输入 "它" (上下文提到了 A100) -> 输出 "NVIDIA A100"。
- *Case*: 输入 "战术优势" -> 输出 "低截获概率(LPI)能力"。
- **禁止**：使用 "本产品"、"该模块"、"特点" 作为 Subject。如果实在无法指代消解，请将其**丢弃**。

### 2. 去营销化 (De-marketing)
- **规则**：删除所有主观形容词（如 "惊人的"、"无与伦比的"、"业界领先的"）。只保留物理事实或战术效能。

### 3. 三维分类映射 (Category Mapping)
- **硬指标 (HARD_SPEC)**: 纯物理参数、规格数据。
  - *例子*: "重 5kg", "频段 30MHz-512MHz", "采用 FPGA 芯片"。
- **战术能力 (TACTICAL_CAPABILITY)**: 装备在战场上**能做什么**（效能/结果）。
  - *例子*: "抗干扰能力", "低截获概率(LPI)", "实时目标识别"。
- **系统机理 (SYSTEM_LOGIC)**: 系统**怎么运作**，以及**由什么组成**。
  - *例子*: "数据经由网关加密后分发", "采用动态时隙分配机制", "由 A 搭载 B 构成"。

### 4. 生成逻辑链 (Logic Chain Generation) - 💎 核心价值
请根据属性类别，灵活选择最自然的逻辑表达方式，**严禁强行套用“因为所以”导致语句不通**：

- **战术能力 / 系统机理**:
  - *模式 A (因果)*: "**因为 [战术背景/痛点]，所以具备了 [能力]**"。
  - *模式 B (手段-目的)*: "**通过 [技术手段/架构]，实现了 [战术效果/性能指标]**"。
  - *模式 C (构成-功能)*: "**作为 [系统角色]，由 [组件] 构成，以支持 [功能]**"。
  - *Case*: "通过引入去中心化路由架构，实现了拒止环境下的高韧性通信。" (优于 "因为是路由，所以韧性高")

- **硬指标**:
  - 若无明确上下文支持，填 "**规格参数直接陈述，无额外战术上下文**"。
  - 若参数隐含战术意义（如 1000:1 压缩比），请解释： "**该指标意味着 [战术意义]**"。

# ⚖️ Quality Rubric (保留 vs 丢弃标准)

**请基于以下标准决定将数据放入 `valid_items` 还是 `dropped_items`：**

### ✅ 进入 Valid Items (评分 ≥ 6)
- **保留原则**：优先保留包含**具体数值、具体型号、具体架构名称**的数据。
- **10分 (完美)**: 主体是具体的专有名词 + 值极其精准 + 逻辑链深刻揭示了“技术-战术”关系。
- **8-9分 (优秀)**: 主体明确，无营销词，逻辑链通顺自然（允许使用“通过...实现...”句式）。
- **7分 (合格)**: 数据干净，无模糊指代，但逻辑链较简单。
- **6分 (瑕疵)**: 主体明确，但保留了少量营销词，或者逻辑链一般。

### ❌ 进入 Dropped Items (评分 < 6)
- **5分 (模糊)**: 主体使用了通用词（如 "该功能"、"特点"），且无法根据上下文修复。 -> **Reason: 主体指代不明**。
- **4分 (逻辑缺失/低信息量)**: 
  - 情况 A: 只有值，没有逻辑链，或逻辑链是同义反复。
  - 情况 B (冗余子集): 该数据是Batch中另一条包含**具体数值/参数**的数据的**模糊描述版本**。
    - *Case*: ID 1 说 "压缩比1000:1"，ID 2 说 "解决了传输困难"。 -> **丢弃 ID 2 (4分)**，保留 ID 1。
  - -> **Reason: 缺乏逻辑深度或信息冗余**。
- **1-3分 (垃圾)**: 纯营销废话，或幻觉严重，无法挽救。 -> **Reason: 无信息增量/营销废话**。
- **重复数据**: 如果当前数据与 Batch 内的其他数据实质内容完全重复（Subject 和 Value 语义一致）。 -> **Reason: 数据冗余**。
